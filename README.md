# Moonsong Labs writing guidelines

This is the style and voice guide Moonsong Labs uses for everything we publish: articles from our engineers, case studies, social posts, landing pages, and decks. We build blockchain infrastructure for regulated financial institutions, and we want our writing to sound the way we work, which is specific and grounded in systems running in production.

We're publishing it because the patterns it targets (inflated vocabulary, "not X, but Y" constructions, filler conclusions) are common across AI-assisted writing, and the fixes are useful well beyond our own team.

## What's in it

`SKILL.md` is the full guide. It covers core principles, voice, openings and endings, guidance for technical writing, notes for each channel, a list of constructions to avoid, house terminology, and a final-pass checklist.

## Download

[Download moonsong-writing.zip](https://github.com/kalebjake/moonsong-writing/releases/latest/download/moonsong-writing.zip) for the packaged skill, or read [`SKILL.md`](SKILL.md) directly.

## How to use it

As a person: read `SKILL.md` once, then run the final-pass checklist at the bottom before you publish anything.

As a Claude skill: the file is formatted as an Agent Skill. Add this folder (or the zipped folder) as a custom skill in Claude, and it will load automatically when you draft or edit content for Moonsong.

With other AI tools: paste the contents of `SKILL.md` into the system prompt or custom instructions, then ask the model to draft or review against it.

## For Moonsong engineers

If you're writing for the Moonsong blog or a partner channel, read the "Writing technical content" and "Review before publishing" sections first. Anything that names a client, describes client architecture, or makes a claim about Moonsong's results goes to marketing before it's published.
